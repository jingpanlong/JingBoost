# 景同志·电脑加速（JingBoost）

一款纯本地运行的 Windows 电脑加速 / 维护工具。界面使用 WebView2 渲染，后端为 Python + ctypes 直接调用 Windows API，无联网、无广告、无捆绑。

- 版本：v1.4.2
- 运行环境：Windows 10 / 11（需要 WebView2 运行时，Win11 与新版 Win10 已内置）
- 作者：公众号「景同志」　小红书「景同学」
- 界面：浅色 / 深色双主题，**默认浅色**，右上角按钮一键切换，选择会记住

## 一、功能总览（40+ 项，全部可用）

### 1. 一键加速
组合执行垃圾清理 / 内存整理 / 高性能电源 / DNS 刷新 / 非必要服务优化 / 全套系统调优，6 个选项自由勾选，输出逐步结果。

### 2. 内存释放
- `EmptyWorkingSet` 逐进程整理工作集（自动跳过系统关键进程与小于 4MB 的进程）
- `NtSetSystemInformation(SystemMemoryListInformation)` 清空系统备用内存列表
- 实时显示释放前后的内存占用对比

### 3. 垃圾清理（14 类，先扫描后清理，带真实进度）
用户临时文件、系统临时文件、回收站、**回收站残留文件**、预读取缓存、缩略图与图标缓存、Windows 更新缓存、传递优化缓存、错误报告与崩溃转储、浏览器缓存（Edge/Chrome/Brave/360）、系统日志与安装残留、开发工具缓存、DNS 解析缓存、升级残留。

进入页面就**自动扫描**，不用先点「开始扫描」。清理过程是**异步任务**：弹窗里的进度条带百分比，按「已处理项数 / 总项数」从 0% 走到 100%，下面实时显示当前正在处理哪一项，而不是转圈等到天荒地老；清理完成时用返回的实测释放量**就地扣减**——那一行立刻变成 `0 B ✓`、文件数变成「已清空」，随后再后台重扫校正（只用来纠正"其实没删掉"的部分）。

**为什么进度条要"慢慢走"（v1.4.1）**：14 个目标扫一遍实测只要 160ms（TEMP 62ms + 回收站 71ms，其余合计 30ms），如果把真实进度直接画上去，就是 `0% → 100%` 一帧跳完，用户只看到一个残影。所以真实进度只当**目标值**，屏幕上的可见值用定时器匀速追过去（每步至少 2%、最多补差值的 18%），走完 100% 再停留 0.26 秒才关遮罩。全程单调不减、不超前于真实进度，快任务约 0.7 秒走完，慢任务自动贴合真实速度。

**回收站为什么要拆成两项（v1.4.0 修正）**：资源管理器的回收站是 `$I` 索引 + `$R` 数据 一对一的目录结构，删文件时两个一起生成。索引文件一旦丢失（中断的删除、异常关机、清理软件误删），`$R` 数据就变成「回收站里看不到、但一直占着盘」的孤儿文件；而 `SHEmptyRecycleBin` 是**按索引删**的，这些孤儿一个都不会动 —— 这正是「回收站明明是空的却显示几十 GB」「点了立即清理数字纹丝不动」的根因。
- 「回收站」口径改为 Windows 自己报的数（`SHQueryRecycleBinW`），也就是资源管理器里看到的那些，不再去遍历 `$Recycle.Bin` 目录；
- 「回收站残留文件」单独列一项，只算**当前用户 SID 目录**下索引已丢失的孤儿数据与失效索引，配对完整的项目一个都不碰；
- 清理报告的是清理前后实测差值，不是扫描时的估算值。

**尺寸为真实值**：扫描只统计"真正会被删掉"的文件 —— `keep` 白名单（如 `Prefetch\LAYOUT.INI`）不计入；同一批文件不再被两条规则重复计算（`CbsPersist*.log` 曾被算两遍）；非管理员账号下被拒绝访问的目录会明确标成「需管理员」，不再假装成 0 B。实测临时目录、更新缓存与 PowerShell 独立遍历的结果逐字节一致。

**`_MEI*` 目录绝对不碰（v1.4.2）**：`%TEMP%` 下 `_MEI` 开头的目录是 PyInstaller 单文件程序的解包目录——里面就是**正在运行的程序本体**（`python313.dll`、`index.html` 等）。它是我们的「用户临时文件」会扫到的地方，但删掉其中的 `web/index.html` 这类尚未加载的文件，程序重载页面时会直接白屏/异常；而且这些文件被进程锁着删不掉，统计时却算进「可清理」，于是出现「扫描 100MB、清理只有 30MB」。现在扫描与删除都跳过它，统计数字和实际释放量才对得上。

### 4. 启动项管理
注册表 `Run / RunOnce`（HKCU、HKLM、WOW6432Node）+ 用户/公共启动文件夹；每项左侧自动识别并显示**程序图标**；支持启用、禁用（移动到备份区，可恢复）、彻底删除。

### 5. 进程管理
实时 CPU / 内存占用（两次采样差值计算）、**每个进程显示其可执行文件图标**、结束进程、设置优先级、系统关键进程保护。

### 6. 服务管理
查看 289+ 服务状态与启动类型、启动/停止/重启、修改启动类型、一键优化非必要服务（遥测、Xbox、传真等）。

### 7. 网络优化
刷新 DNS、TCP 全局参数优化（自动调优/RSS/ECN/时间戳）、重置 Winsock、重置 TCP/IP、一键切换阿里/腾讯/114 DNS、恢复自动 DNS、hosts 查看 / 重置 / 恢复。

### 8. 网络测速
对百度、腾讯、阿里 DNS、114 DNS、GitHub、Google、Google DNS 共 7 个节点做 TCP 握手延迟测试，比 ICMP 更贴近真实可用性；节点并发探测，超时节点不会拖慢整体结果。

### 9. 系统调优（8 项，全部可一键还原）
性能优先视觉特效、取消开机启动延迟、游戏模式与关闭后台录制、关闭遥测与广告推送、启用超长路径、关闭搜索索引、关闭 SysMain、恢复 Win11 经典右键菜单。

### 10. 电源与系统
高性能 / 平衡 / 节能 / 卓越性能四种电源计划、关闭休眠释放磁盘、重启资源管理器。

### 11. 系统修复
SFC 系统文件检查、DISM 映像修复、CHKDSK 磁盘检查、磁盘优化（SSD 自动走 TRIM，机械盘走碎片整理）、创建系统还原点，全部带实时日志输出。

### 12. 磁盘健康
物理磁盘健康状态、介质类型、容量、SMART 故障预测、系统还原点列表。

### 13. 磁盘分析
- 大文件扫描（阈值 50MB / 100MB / 500MB / 1GB 可选）
- 重复文件扫描（大小分组 → 头部 MD5 → 全量 MD5 三级比对，可逐个删除）
- 空文件夹扫描

### 14. 系统信息
操作系统、激活状态、厂商/机型、主板、BIOS、CPU 型号/核心/线程/主频、内存、显卡、分辨率、网卡、物理磁盘、分区占用。
采集采用 **CIM/WMI → SMBIOS 注册表 → psutil/ctypes** 三层兜底，自动过滤 `To Be Filled By O.E.M.` 等占位值与虚拟显卡，组装机等 SMBIOS 缺省机型也能给出可读结果，不再大片显示「未知」。

### 15. 实时监控与体检
CPU / 内存 / 系统盘 / 网络四项环形仪表，1.6 秒刷新；综合健康评分 + 问题清单；一键导出体检报告到桌面。**只有点了「导出体检报告」才会写文件**（v1.4.1 前冒烟测试直接调 `export_report()`，而它默认落在桌面，导致没点也在桌面冒出报告；现在落点可传参、测试一律写临时目录）。

卡片副标题给的是关键硬件指标：处理器核心/线程 + 主频 + **CPU 温度**、内存已用/总量 + **内存条数与类型**、系统盘可用 + **物理硬盘数量**、**网络上下行实时速率**（1000 进制，和网卡速率习惯一致）。

- 首屏只用注册表 + psutil 拼一份轻量快照，**0.7 秒出图**，不碰 WMI；内存条、物理磁盘数、温度这些要跑 PowerShell 的字段由后台预热线程补齐，前端每 2.5 秒补刷一次直到拿全（最多 6 次）。
- 完整硬件信息用 4 个线程并发采集（每开一次 PowerShell 光启动就要 1~2 秒），实测从 6.3 秒降到 3.4 秒。
- CPU 温度只有装了 LibreHardwareMonitor / OpenHardwareMonitor 或主板暴露 ACPI 热区时才读得到；读不到就显示「主板未暴露传感器」，不会假装成「未知」让用户以为采集坏了。

### 16. 注册表备份与还原
所有调优改动前自动记录原值（`%APPDATA%\JingBoost\backups\registry.json`），支持一键还原全部改动。

### 17. 权限管理
非管理员启动时侧栏可点击提权重启，深度功能（系统文件、服务、HKLM 注册表）自动按权限降级并提示。提权采用互斥体交接机制，不会再出现「程序已经在运行了」导致管理员进程起不来；UAC 点「否」时程序保持运行。旧进程的所有界面（含悬浮胶囊）会先撤掉再退出，由管理员进程重新接管（详见第 21 节）。

### 18. 系统托盘
点顶部「收进托盘」或右上角 ×（可在设置里改）后，主界面隐藏到任务栏托盘，程序与悬浮胶囊继续运行。托盘图标左键恢复主界面，右键菜单含：显示主界面 / 显示·隐藏悬浮胶囊 / 一键加速 / 开机自动启动 / 退出程序。首次收起会有一条气泡提示。

### 19. 开机自启动
设置面板一键写入 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`（仅当前用户，无需管理员）；源码运行时指向 `python.exe + main.py`，打包后自动指向 exe。卸载时自动清除。

### 20. 桌面悬浮胶囊（v1.4.0 支持自定义外观）
独立的置顶无边框窗口，**宽度随内容自适应（约 312 × 54，最窄可收到 150）**。左起依次是：环形健康评分（环色随分数变绿 / 橙 / 红，环内闪电）、CPU、内存、网速（下行，悬停看上下行）、一键加速、关闭。数据 2 秒刷新，评分 30 秒缓存并在启动时后台预热，首帧不会空白。
- **外观可自定义**（设置面板「悬浮胶囊外观」分组，改动即时生效并持久化）：
  - **透明度** 30%~100%。走 DWM 整窗恒定 alpha（`SetLayeredWindowAttributes`），不是 CSS 半透明 —— 窗口底下是 WinForms 灰底，CSS 调 alpha 只会变成"灰底上盖一层半透明卡片"。这里有个坑：`WS_EX_LAYERED` 必须常驻，不能在 100% 时摘掉、再调低时加回来，WebView2 走 DirectComposition，样式位来回增删后合成层不再接受恒定 alpha（`GetLayeredWindowAttributes` 读回来是对的，屏幕上却一点都不透）。
  - **主题色**：7 套预设（宝石蓝 / 湖青 / 薄荷绿 / 星紫 / 琥珀橙 / 樱粉 / 石墨）+ 自定义取色器，自定义色自动推出渐变的辅色。
  - **显示内容**：健康评分 / CPU / 内存 / 网速 可任意开关，全关就只剩一颗「加速」按钮。列宽固定（网速从 `999K` 变 `1.0M` 时整颗胶囊不会跟着抖），窗口宽度由胶囊前端量 `max-content` 后回传给后端改尺寸，DPR 缩放再变也对得上。
- **无「透明边」**：本机 WebView2 上 `transparent=True` 并不真正生效，窗口底下仍是 WinForms 的默认灰底（`#E4E6E8`），CSS 圆角再漂亮也会露出一圈方框。改为 `CreateRoundRectRgn` + `SetWindowRgn` 把窗口本身裁成 15px 圆角、内容 `inset:0` 铺满，边缘彻底干净；代价是窗口外阴影会被裁掉，改用顶部高光 + 内描边 + 底部内阴影补层次。
- **加速特效**：点击瞬间按钮涟漪扩散 + 整颗胶囊斜向扫光 + 状态环脉冲；加速中按钮呈蓝色呼吸光环；完成后按钮变绿、闪电换成对勾并弹一下，2.2 秒后复原。托盘里发起的一键加速也会在胶囊上同步这套动效。
- **拖动**：在胶囊任意非按钮位置按住左键即可拖到桌面任意位置，位置写入设置，重启后恢复。
- **贴边自动隐藏**：靠近屏幕左 / 右 / 上边缘 22px 内、连续停留 0.6 秒后自动滑出，只留 7px 提示条（可在设置里关闭）。状态机做了三层防抖：
  - 鼠标还搭在胶囊上也能收起（拖完手没移开不会卡住不隐藏）；
  - 收起后要求鼠标**先离开提示条再回来**才滑出，避免刚收起就被拉回来；
  - 滑出时把位置夹回完整可见的**安全区**（留 28px 边距，大于 22px 触发阈值），并给 4 秒宽限期；启动与位置持久化也走同一套夹取，避免把"藏在屏幕外"的坐标写进设置导致下次开机胶囊看不见、或一启动就自己收起来。
- **主题同步**：跟随主界面的浅色 / 深色切换。托盘里发起的一键加速也会同步显示进度。
- **不占任务栏**：`WS_EX_TOOLWINDOW` + `SWP_FRAMECHANGED` + `ITaskbarList::DeleteTab` 三重处理，胶囊不再作为独立任务栏按钮 / Alt-Tab 窗口出现，任务栏只保留主界面一个入口；explorer 重启后自动补刷。
- **关闭行为**：叉掉胶囊只隐藏不销毁，同时无条件把主界面带回前台，避免「胶囊关掉后新界面看不见」。

以上 18~20 项统一在顶部齿轮「设置」里开关，改动即时生效并持久化。

### 21. 提权交接（v1.3.0 重做时序）
点「提权」后的完整顺序是：**先交出单实例互斥体 → 弹 UAC → 通过后旧进程把托盘、主窗口、胶囊全部撤掉 → 0.2 秒后 `os._exit(0)` 真退出 → 管理员子进程接管并显示自己的主窗口与胶囊**。任一步失败都不会留下「界面没了但进程还在」的半死状态；UAC 点「否」时收回互斥体，程序保持原样继续运行。

互斥体用会话内的 `Local\` 而不是 `Global\`（v1.4.2）：`Global\` 命名对象需要 `SeCreateGlobalPrivilege`，普通用户进程创建会返回 NULL + `ERROR_ACCESS_DENIED`，旧代码把「错误码不是 183」当成抢锁成功，锁实际没建起来，连点两次就是两个实例。现在只有真正创建成功才算抢到；若锁被崩溃残留占着但窗口已不在，会强制接管继续启动，而不是弹一句「程序已经在运行了」把人挡在门外。

这里有个很容易踩的坑：`FindWindowW` 是按标题全系统搜索的，旧进程的窗口标题与新进程完全一样，新进程很可能先认到**旧进程**的句柄。后果是新的悬浮胶囊从没被设成工具窗口（任务栏留下一个按钮），`main_hwnd` 又指向下一秒就被销毁的旧句柄（主窗口再也叫不回来）。所以认窗口一律走 `find_own_window()`：`EnumWindows` + `GetWindowThreadProcessId` 过滤到本进程。

验证不靠肉眼：`verify/check_handoff.py` 用桩替代 UAC，真实拉起交接子进程，从外部枚举窗口确认「旧进程退出 + 旧窗口消失 + 新主窗口可见 + 新胶囊可见 + 任务栏仅 1 个按钮」。

pip install pywebview psutil pyinstaller

```bash
python build/build_all.py
```

## 五、安全设计

- 所有注册表改动写前记录原值，可一键还原
- 不结束系统关键进程（csrss / winlogon / lsass / services 等有白名单保护）
- 不删除系统文件，清理前先扫描预览，危险项默认不勾选
- 所有磁盘操作均为本地文件读写，不联网、不上传任何数据
- 一键加速中不包含「自动杀进程」，避免误伤用户正在使用的工作

### 本地数据存放位置

| 内容 | 路径 |
| --- | --- |
| 界面设置（主题、托盘/胶囊开关、胶囊位置） | `%APPDATA%\JingBoost\settings.json` |
| 开机自启动 | `HKCU\Software\Microsoft\Windows\CurrentVersion\Run\JingBoost` |
| 注册表改动备份、禁用的启动项 | `%APPDATA%\JingBoost\backups\` |
| 崩溃日志 | `%TEMP%\jingboost.log` |
